# UAT — ทดลองใช้ก่อนเปิดให้ทั้งฝ่าย

ชุดทดสอบอัตโนมัติพิสูจน์ตรรกะของระบบไปแล้ว เอกสารนี้ใช้พิสูจน์ **สิ่งที่พิสูจน์ด้วยโค้ดไม่ได้** —
ว่าบนบัญชี Google จริงของบริษัท ระบบส่งอีเมลออกจริง สร้างโฟลเดอร์จริง และคนแต่ละบทบาท
ทำได้/ทำไม่ได้ตามที่ควรจริง

ใช้เวลาประมาณ **45–60 นาที** ควรทำก่อนเปิดให้ทั้งฝ่ายใช้ และทำซ้ำทุกครั้งที่ deploy ครั้งใหญ่

---

## เตรียมก่อนเริ่ม

- [ ] รัน `verifyDeployment()` แล้วไม่มีข้อ **"ไม่ผ่าน"** เหลืออยู่
- [ ] มีคนทดสอบอย่างน้อย 3 บัญชี — **Buyer A**, **Buyer B**, **หัวหน้า (HEAD)**
      (หัวหน้าต้องไม่เป็นเจ้าของงานที่จะใช้ทดสอบการอนุมัติ)
- [ ] เปิดชีต `Change_Log` ค้างไว้อีกแท็บ เพื่อดูว่าทุกขั้นถูกบันทึกจริง
- [ ] เตรียมไฟล์ PDF เล็กๆ 1 ไฟล์ สำหรับทดสอบการแนบใบเสนอราคา

> ใช้ข้อมูลที่ดูออกว่าเป็นการทดสอบ เช่น ขึ้นต้นรายละเอียดงานด้วย `[UAT]`
> เมื่อเสร็จให้หัวหน้ายกเลิกงานเหล่านี้ทิ้ง (ระบบไม่ลบข้อมูลจริง จึงยังตรวจย้อนหลังได้)

## 1. เปิดงานและบันทึกรายการ

**ทำ (Buyer A):** เปิด Case ใหม่ → กรอกครบทุกช่องที่มีดอกจัน → บันทึก → ไปแท็บ "รายการ Item"
เพิ่ม 2 รายการ (เช่น โครงสร้างเหล็ก 2 ชุด, งานติดตั้ง 1 งาน)

**ต้องเห็น**
- [ ] รหัสงานเป็น `SRC-<ปีปัจจุบัน>-0001` (งานถัดไปต้องเป็น `-0002`)
- [ ] สถานะเริ่มต้นคือ **รอข้อมูลจากผู้ขอ**
- [ ] ปุ่ม "โฟลเดอร์ไฟล์" กดแล้วเปิดโฟลเดอร์ใน Drive ที่ชื่อขึ้นต้นด้วยรหัสงาน
- [ ] โฟลเดอร์นั้น **คนนอกโดเมนบริษัทเปิดไม่ได้**
- [ ] ในชีต `Change_Log` มีแถว `CREATE` ของตาราง `Cases` ชื่อผู้ทำรายการคือ Buyer A
- [ ] ลองเลือกประเภทงบ CAPEX แล้วดูว่า "ประเภทย่อย" เปลี่ยนตาม (ไม่ขึ้นตัวเลือกของ OPEX)

## 2. เชิญผู้ขาย 3 ราย แล้วปิดขั้นตอนหา Vendor

**ทำ (Buyer A):** เมนู "ผู้ขาย" → เพิ่มผู้ขาย 3 ราย (เลขผู้เสียภาษีต่างกัน) →
กลับมาที่งาน แท็บ "Vendor & ราคา" → เพิ่มผู้ขายทั้ง 3 เข้างาน →
แก้สถานะแต่ละรายเป็น "เสนอราคาแล้ว" พร้อมเลขที่และวันที่ใบเสนอราคา →
กรอกราคาในตารางให้ครบทุกช่อง → กด "บันทึกราคา" →
เปลี่ยนสถานะงานเป็น "กำลังหา Vendor" แล้วเป็น "หา Vendor ครบแล้ว"

**ต้องเห็น**
- [ ] ป้าย "ใบเสนอราคาที่ใช้ได้ 3 / 3" เป็นสีเขียว
- [ ] ยอดรวมต่อผู้ขายถูกต้อง (= จำนวน × ราคาต่อหน่วย รวมทุกรายการ)
- [ ] ช่องราคาต่ำสุดของแต่ละรายการถูกไฮไลต์สีเขียว
- [ ] ยอดรวมเปลี่ยนทันทีขณะพิมพ์ ก่อนกดบันทึกด้วยซ้ำ
- [ ] เปลี่ยนสถานะเป็น "หา Vendor ครบแล้ว" ได้สำเร็จ
- [ ] แนบไฟล์ใบเสนอราคาได้ และลิงก์ "เปิดไฟล์" กดแล้วเปิดไฟล์นั้นจริง

**ลองแหกกฎดู**
- [ ] เพิ่มผู้ขายรายเดิมเข้างานซ้ำ → ระบบ **ปฏิเสธ**
- [ ] เพิ่มผู้ขายใหม่โดยใช้เลขผู้เสียภาษีที่มีอยู่แล้ว → ระบบ **ปฏิเสธ** และบอกว่าเป็นผู้ขายรายใด
- [ ] เพิ่มผู้ขายที่ใช้ **เบอร์โทรเดียวกัน** กับรายอื่น → ระบบ **เตือน** แต่ยังบันทึกได้

## 3. กรณีได้ไม่ครบ 3 ราย — ขอยกเว้น

**ทำ (Buyer A):** เปิดงานใหม่ ใส่ 1 รายการ เชิญผู้ขายแค่ 2 ราย เสนอราคาครบทั้งคู่ →
เปลี่ยนสถานะเป็น "กำลังหา Vendor" → ลองเปลี่ยนเป็น "หา Vendor ครบแล้ว"

**ต้องเห็น**
- [ ] ระบบ **ปฏิเสธ** พร้อมบอกว่ามี 2 ราย จากที่กำหนด 3 ราย

**ทำต่อ (Buyer A):** กด "ขอยกเว้นจำนวนใบเสนอราคา" เลือกเหตุผลและกรอกคำอธิบาย

- [ ] ไม่กรอกคำอธิบาย → ระบบไม่ยอมให้ส่ง
- [ ] ส่งสำเร็จแล้ว **หัวหน้าได้รับอีเมล** (เช็คกล่องจดหมายจริง)
- [ ] ระหว่างรออนุมัติ ยังเปลี่ยนสถานะไม่ได้

**ทำต่อ (หัวหน้า):** เปิดงานนั้น กด "พิจารณาคำขอยกเว้น" → อนุมัติ

- [ ] **Buyer A ได้รับอีเมลแจ้งผล**
- [ ] จากนั้น Buyer A เปลี่ยนเป็น "หา Vendor ครบแล้ว" ได้

**ข้อสำคัญที่สุดของหัวข้อนี้ (หัวหน้าทำ):** เปิดงานที่ **หัวหน้าเป็นเจ้าของเอง** แล้วขอยกเว้น
จากนั้นลองกดอนุมัติเอง

- [ ] ระบบ **ปฏิเสธ** — ผู้ขอกับผู้อนุมัติต้องไม่ใช่คนเดียวกัน

---

## 4. ใบเสนอราคาหมดอายุ → ระบบย้อนสถานะเอง

นี่คือกลไกที่เงียบที่สุดและพลาดง่ายที่สุด จึงต้องเห็นกับตา

**ทำ (Buyer A):** ใช้งานจากข้อ 2 (สถานะ "หา Vendor ครบแล้ว") →
แท็บ "Vendor & ราคา" → แก้ผู้ขาย 1 ราย ใส่ "ยืนราคาถึงวันที่" เป็น**วันที่ผ่านมาแล้ว**
พร้อมระบุเหตุผล → บันทึก

**ต้องเห็น**
- [ ] สถานะงานย้อนกลับเป็น **"กำลังหา Vendor"** ทันที โดยไม่มีใครสั่ง
- [ ] ป้ายใบเสนอราคาเหลือ **2 / 3**
- [ ] มีคำอธิบายว่าใบของผู้ขายรายนั้น "หมดอายุแล้ว"
- [ ] **Buyer A ได้รับอีเมล** แจ้งว่าระบบย้อนสถานะให้
- [ ] ในชีต `Change_Log` แถวนั้นชื่อผู้ทำรายการคือ **`SYSTEM`** ไม่ใช่ชื่อคน
- [ ] เปิดอีเมลฉบับนั้นแล้ว **ไม่มีชื่อผู้ติดต่อ เบอร์โทร อีเมล หรือที่อยู่ของผู้ขาย** (PDPA)

---

## 5. สิทธิ์ของแต่ละคน

**ทำ (Buyer B):** เปิดงานของ Buyer A

- [ ] เห็นข้อมูลได้ แต่มีป้าย "อ่านอย่างเดียว" และไม่มีปุ่มแก้ไข
- [ ] แท็บ Activity **ยังบันทึกกิจกรรมได้** (เพราะต้องช่วยงานกันได้)
- [ ] กิจกรรมที่บันทึกขึ้นชื่อ **Buyer B** ไม่ใช่ Buyer A
- [ ] Buyer B แก้ไขกิจกรรมที่ตัวเองบันทึกได้ แต่แก้ของ Buyer A ไม่ได้

**ทำ (หัวหน้า):** เมนู "ภาพรวมทีม"

- [ ] เห็นงานแยกตาม Buyer พร้อมจำนวนงานเปิดอยู่ / เลยกำหนด / รออนุมัติยกเว้น
- [ ] Buyer ทั่วไปเปิดเมนูนี้ไม่เห็น

---

## 6. โอนงาน

**ทำ (หัวหน้า):** ภาพรวมทีม → เลือกงานของ Buyer A → "โอนงาน" ให้ Buyer B พร้อมเหตุผล

- [ ] ไม่กรอกเหตุผล → ระบบไม่ยอม
- [ ] **Buyer B ได้รับอีเมล** และ **Buyer A ได้รับอีเมล** แจ้งว่าถูกโอนไปแล้ว
- [ ] เจ้าของงานเปลี่ยนเป็น Buyer B
- [ ] ตอนนี้ **Buyer B แก้ไขงานได้** และ **Buyer A แก้ไม่ได้แล้ว**
- [ ] ชีต `Change_Log` มีแถว `REASSIGN` พร้อมเหตุผล

---

## 7. เลข PR

**ทำ (Buyer A):** เปิดงานที่ยังอยู่สถานะ "กำลังหา Vendor" → แท็บ "เลขเอกสาร (PR)"

- [ ] ยังเพิ่มเลข PR ไม่ได้ (ระบบบอกว่าต้องถึงสถานะ "หา Vendor ครบแล้ว" ก่อน)

**ทำต่อ:** เปลี่ยนสถานะเป็น "หา Vendor ครบแล้ว" แล้วเพิ่มเลข PR

- [ ] เพิ่มได้สำเร็จ
- [ ] เพิ่มเลข PR ที่สองในงานเดียวกันได้ (1 งานมีได้หลาย PR)
- [ ] เอาเลข PR เดิมไปใส่ใน **งานอื่น** → ระบบ **ปฏิเสธ** และบอกว่าเลขนี้ใช้ในงานไหนอยู่

---

## 8. ปิดงานและเปิดใหม่

**ทำ (หัวหน้า):** ปิดงานจากข้อ 2 (เปลี่ยนสถานะเป็น "ปิดงาน")

- [ ] **Buyer A แก้อะไรในงานนั้นไม่ได้อีกเลย** รวมถึงบันทึกกิจกรรม
- [ ] Buyer A ไม่มีปุ่ม Reopen

**ทำต่อ (หัวหน้า):** กด "Reopen" พร้อมเหตุผล

- [ ] งานกลับไปที่สถานะ **"หา Vendor ครบแล้ว"** (สถานะก่อนปิด ไม่ใช่สถานะเริ่มต้น)
- [ ] Buyer A แก้ไขได้อีกครั้ง
- [ ] ชีต `Change_Log` มีแถว `REOPEN` พร้อมเหตุผล

---

## 9. การแก้ไขพร้อมกันสองคน

**ทำ:** ให้หัวหน้าและ Buyer A เปิดหน้ารายละเอียดงานเดียวกันพร้อมกัน →
ให้ Buyer A กดแก้ไขและบันทึกก่อน → จากนั้นให้หัวหน้ากดบันทึกจากหน้าจอที่ค้างอยู่

- [ ] หัวหน้าได้ข้อความ **"ข้อมูลถูกแก้ไขโดยผู้อื่น กรุณาโหลดใหม่"**
- [ ] ข้อมูลที่ Buyer A บันทึกไว้ **ไม่ถูกเขียนทับ**

---

## 10. อีเมลสรุปรายวัน

**ทำ:** บันทึกกิจกรรมที่มี "สิ่งที่ต้องทำต่อ" โดยตั้งวันครบกำหนดเป็นเมื่อวาน →
จาก Apps Script editor รัน `dailyReminderJob()` ด้วยมือ (ไม่ต้องรอถึงเวลาจริง)

- [ ] เจ้าของงานได้รับอีเมล **ฉบับเดียว** ที่รวมทุกเรื่องไว้ (ไม่ใช่ฉบับละเรื่อง)
- [ ] ในอีเมลมีเฉพาะงานของคนนั้น ไม่มีงานของ Buyer คนอื่น
- [ ] รายการที่เลยกำหนดแยกจากรายการที่ใกล้ครบกำหนด
- [ ] ติ๊ก "เสร็จแล้ว" ที่กิจกรรมนั้น แล้วรัน `dailyReminderJob()` ใหม่ → ไม่มีอีเมลอีก
- [ ] ในหน้า "งานของฉัน" แถวที่เลยกำหนดมีแถบสีแดงด้านซ้าย
